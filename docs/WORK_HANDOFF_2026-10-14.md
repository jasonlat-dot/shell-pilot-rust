## 2. 当前架构与已确定的边界

```text
React / xterm
  → Tauri invoke / Channel
    → 同进程 Rust 业务库
      → SQLite 与本地文件
      → SSH / SFTP 目标服务器
      → 模型供应商 HTTP(S) 接口
```

- 客户端与 Rust 业务库编译为同一个桌面程序，不需要先启动独立后端。
- 产品不监听本地后端 HTTP 端口，不提供远程 ShellPilot 后端模式、地址或后端证书设置。
- Rust 独立 HTTP 程序入口已移除，业务库仍可以单独编译和测试。
- 历史 HTTP 适配和回环协议夹具属于测试/参考，不是产品运行链路。
- 开发模式使用 Vite 服务加载前端；安装版没有这个开发服务器。
- 内部工作区身份用 `ipc://builtin/<实例ID>` 表示，它不是网络网址。
- Rust Preview 当前版本为 0.4.0，自动更新关闭；当前源码未重新生成安装包。

### 业务交互方式

| 业务 | 交互方式 |
| --- | --- |
| SSH 配置、连接、输入、resize、关闭 | Tauri invoke → Rust |
| SSH 输出和断线状态 | Channel，xterm 写入后确认当前帧 |
| 本地命令终端 | Tauri 原生本地终端 |
| SFTP 操作、传输、取消 | Rust 文件句柄与 SFTP 流；进度走 Channel |
| 独立文件与附件存储 | 原生文件选择/保存、invoke 和本地文件流 |
| 模型配置、Agent 会话与历史 | invoke → Rust SQLite |
| AI 文本回复 | Rust 调用模型，Channel 返回文本和终态 |

这次改造解决了 WebView HTTP/1.1 长轮询占满同源连接的问题。针对同一服务器开到约第 10 个终端的失败，已加入有界 SSH 传输池与通道配额，并在通道拒绝场景尝试新的传输。SSH 服务器本身的会话限制依然存在。

工作区重新初始化会清理 SSH/SFTP 等运行资源，旧会话不能被偷偷路由到新的实例；磁盘数据保留。

内核完成不等于真实工具执行或自动压缩已经开放。真实 SSH 副作用去重的最终联验仍属于 D3。

### B1：模型配置与适配器

- 支持 OpenAI 兼容 Chat Completions、基础非流式协议、usage 和工具协议结构校验。
- API 基础地址与相对接口路径分开保存，保留代理前缀并拒绝跨站/歧义路径。
- 模型窗口、输出/安全预留、超时、响应上限与采样参数由配置声明，不根据模型名猜测能力。
- 支持 `max_completion_tokens` 与旧兼容接口的 `max_tokens`。
- API Key 使用 Windows DPAPI 加密，与 Windows 用户、应用用户和稳定配置 ID 绑定。
- 配置读取不返回密钥；解密只发生在原生运行层，密钥不进入 IPC 响应或事件日志。
- 支持保留、设置/替换、清除密钥；更换基础地址时必须明确替换或清除旧密钥。
- 保持 TLS 校验，不自动跟随重定向或重试模型调用，第三方错误经过收敛处理。

详细说明：AGENT_MODELS.md。

### B2：基本文本会话与流式 IPC

- 对接模型列表、创建会话、文本流和停止接口。
- Services 管理同进程 Agent 生命周期。
- SSE 按字节处理 UTF-8 和 LF/CRLF，不依赖网络分块边界。
- 保留 `text / done / error` 前端事件协议，通过 Channel 和 ACK 控制流量。
- 当前只开放文本生成；模型返回工具调用不等于已经执行命令。

详细说明：AGENT_CHAT.md。

### B3：生成轮次、停止与恢复

- 持久 `requestId` 与短期订阅 `streamId` 分离。
- 同一会话最多一个 running 轮次；已完成请求重读返回缓存，不重复调用模型。
- 失败、取消和中断不自动重试；用户重新发送使用新 requestId。
- 停止绑定对应 requestId，旧停止回执不影响下一轮。
- 完成、停止与上下文变更通过事务和版本检查处理竞态。
- 保存部分文本、完整结果、错误码及 usage，部分文本不冒充成功回复。
- EOF、截断、过滤、非法 JSON 等不能当作完整成功。
- 每秒心跳、30 秒租约；硬退出遗留的生成在租约过期后标记中断，不自动重发。
- 前端检查 Channel 关联与序号，隔离重复、缺帧和迟到回调。
- 原生历史支持会话、轮次与事件分页，JSON/代码回复保留原文。

基础文本与回复受 16000 UTF-8 字节等限制约束。自动压缩尚未接入，历史或预算超限会明确拒绝并提示新建会话。

详细说明：AGENT_TURNS.md。

### B4：模型设置、AI 面板与可见历史

- 模型设置支持创建、编辑、删除、密钥操作和高级参数，无需 `.env`。
- 配置保存后用于后续请求；“已配置”表示字段/密钥满足要求，发送时才验证真实连接。
- AI 面板支持基础文字提问、纯文本粘贴、模型选择、流式回复和停止。
- 使用 Rust SQLite 历史作为权威状态，不依赖旧客户端缓存判断是否成功。
- 支持历史分页、生成中刷新/停止，以及失败、取消、中断状态展示。
- 继续旧会话使用原目标；切换终端页签不能改变会话绑定。原终端失效后需新建会话。
- 聊天附件、工具执行/审批和自动压缩仍未开放。

操作说明：agent-model-settings.md。

## 5. 配置改名与 schema 7

| 字段 | 含义 |
| --- | --- |
| id | 稳定内部身份，关联密钥加密与历史，改名时不变 |
| displayName | 用户可编辑的配置名称 |
| config.model / modelName | 供应商模型 ID，与配置名称不同 |
| revision | 更新和删除时检查的配置版本 |

- 当前数据库 schema 为 7，新增 agent_model_names 表。
- 原配置和会话保留，旧配置没有名称记录时回退到原 ID。
- save_named 在同一事务中保存名称和配置；旧 save 调用保留已有名称。
- IPC 保存请求可以携带 displayName，名称限制为 1–64 个非控制字符并去除首尾空白。
- 新建配置使用独立 UUID；改名不会创建新配置，不改变密钥绑定或会话归属。
- 配置列表和 AI 面板同步显示新名称。
- 删除后重建同名配置会产生新 ID，不自动关联被删配置的历史；历史仍保留在数据库中。

## 6. 在另一台电脑运行与配置

先同步客户端和 Rust 库，按本机实际位置配置 Cargo 依赖。运行环境需要 Node/npm、Rust Windows MSVC 工具链、C++ 编译工具和 WebView2。

本机已验证的版本是 Node.js 24.14.1、rustc/cargo 1.98.1。工具位置由本机环境决定，命令使用 PATH 中的工具。

在客户端开发工作区执行：

```powershell
npm ci
npm run prepare:backend
npm run tauri dev
```

这些命令安装依赖、准备说明/许可证资源，并编译启动桌面开发程序，不制作安装包。只运行 `npm run dev` 是浏览器预览，不能完整使用原生业务；当前 Rust 库没有独立 `cargo run` 启动方式。

前端通常由 Vite 更新；Rust 业务或原生 IPC 修改后，需要重新编译/重启桌面开发程序。

配置模型的步骤：

1. 打开“设置 → 模型设置”。
2. 填写配置名称、模型 ID、API 基础地址与相对接口路径。
3. 示例：基础地址 `https://model.example.com/v1/`，相对路径 `chat/completions`，避免重复 `/v1`。
4. 设置本机使用的 API Key；无认证本地模型服务可关闭认证。
5. 按供应商说明填写窗口和输出限制，保存配置。
6. 打开 AI 面板，验证对话、停止、历史读取和配置改名。

模型与 SSH 凭据使用 Windows DPAPI。另一台电脑不能将加密数据当作可直接解密的明文配置，应重新配置本机凭据。实际数据与日志位置通过设置页查看；修改数据位置不会自动搬迁已有数据。
